# Архитектура

```text
Системный выход → PulseAudio monitor → parec (PCM 24 kHz, mono, s16le)
                                      ↓
                           локальный Silero VAD (16 kHz)
                                      ↓
                    фрагменты / непрерывный Live → OpenAI STT
                                      ↓
                         gpt-4o-mini → история субтитров
```

- `captions.py`: запуск интерфейса и короткие диагностические режимы.
- `gui.py`: Tkinter, окно управления, история и X11 input shape для пропуска кликов.
- `audio.py`: выбор monitor, поток PCM по 100 мс, VAD, ресемплинг и границы реплик.
- `pipeline.py`: одна STT-сессия, ручные commits, порядок результатов, перевод.
- `config.py`: чтение ключа и сохранение настроек без секретов.
- `journal.py`: журнал метаданных с правами 0600.
- `summarize.py`: p50/p95 этапов обработки из указанных журналов.

Захват проверяет выход по умолчанию раз в секунду и переоткрывает monitor при
смене. При выбранном конкретном выходе автоматического следования нет.
ONNX работает на CPU с одним потоком. Состояние VAD и FIR-фильтра сохраняется
между блоками и сбрасывается при смене выхода.

Перевод выполняется последовательно, финальные результаты имеют приоритет над
промежуточными. Live объединяет изменения текста, не создавая запрос на каждый
дельта-токен. ID реплики включает сеанс: предварительные и финальные результаты
обновляют одну запись истории. Завершённые реплики формируют контекст перевода.

Очередь захвата ограничена 15 секундами, очередь перевода — 12 фрагментами.
При переполнении приложение явно останавливает обработку. При смене модели
предыдущая сессия завершается до открытия следующей. Физическая смена выхода
может создавать короткие разрывы; точность временных меток ограничена приходом PCM.

Журналы `logs/*.jsonl` содержат конфигурацию, `first_delta`, `asr_final`,
`translation`, `display`/`test_output`, загрузку VAD и использование API.
Речь, сырой звук и ключи в журналы не записываются. История субтитров живёт в памяти.

Примеры диагностики (первые два захватывают текущий звук, второй расходует API):

```sh
./run.sh --probe 8
./run.sh --test-mode transcribe --seconds 12
.venv/bin/python summarize.py logs/имя-журнала.jsonl
```

Логи подставных тестов не следует смешивать с реальными измерениями.
